# CIスライド作成ガイド（社員向け・GitHub不要）

> 対象：全社員（Mac）。必要なもの＝ **Mac ＋ Chrome ＋ Claude（Drive連携ON）＋ 共有ドライブ AI-Objective-MGMT** のみ。
> フォントの追加インストールは不要（CIフォントは英字=Hoefler Text／和文=ヒラギノ・游明朝＝**すべて Mac 標準搭載**）。

## この手順の位置づけ（OODA 月次ループの一部）

スライド制作は **Observe→Orient→Decide→Act の月次ループ**（正式定義 = git `docs/slide-process-ooda.md`・
図 = 事業説明デッキ・テンプレ P5）の一部です。下の3ステップは **①生成（Orient の資料化）→
②目視確認（Decide＝あなた＝担当コンサルタントが自動生成資料に修正を加えて完成させる
「確認提出」）→③配布（Act）** に当たります。**AIの生成物をそのまま提出しない**
（②が人間の判断工程）ことがこの手順の要です。

## あなたがやること（3ステップ）

### ① Claude にデッキ HTML を作ってもらう
Claude（claude.ai）で Google Drive 連携を ON にし、次のように依頼する：

```
共有ドライブ AI-Objective-MGMT の「CI正本(配布)」（5co-CI-kit）フォルダの
VERSION に書かれている現行フォーマット（テンプレ・CSS）を正として、
今週の集計データ（deck_data.json / 集計シート）から週次定例デッキの HTML を作成してください。
テンプレの CSS・色・フォント・レイアウトは一切変更せず、文言と数値だけ差し替えてください。
数値は集計データの値をそのまま使い、推測や丸め直しをしないでください。
文章の羅列にせず、主張・数値・比較は内容に合うフレームワーク図・グラフ・表で
構造化して示してください（伝わりやすさ最優先）。
各本文スライドは 129種 SLIDE-PATTERN の考え方で内容に最適な図の型を選び、
選んだ型と「なぜその型か」の理由を明示してください。
生成前に、集計データ・OKR進捗・年間計画書・前回定例会の文字起こしが揃っているか
確認し、欠けている場合は生成せず「データ欠損アラート」を出してください。
```

### ② Mac で開いて確認（＝この時点で忠実表示）
生成された HTML をダウンロードして **Chrome か Safari で開く**。
Mac 標準フォントで CI 通りに表示される。**PDF が欲しい場合はここで完了**：
`⌘P → 送信先「PDFに保存」`（横向き・背景グラフィック ON）。

### ③ 正式な PPTX / Google スライドが必要な場合
HTML を共有ドライブの **`_仕上げ待ち`** フォルダに置く（ファイル名例：`NatureLab様_2026-Www.html`）。
→ ファイナライザ担当が変換し、**PPTX と Google スライド**を `_完成品` フォルダに返す。

## データが足りないと言われたら（入力ゲート）

- Claude は生成前に **Observe/Orient の入力**（集計データ・OKR進捗・年間計画書・
  前回定例会の文字起こし）をチェックし、欠けていると**「データ欠損アラート」**を出します。
  アラートが出たら担当コンサルタントへ連絡してください（連絡文は Claude が作ります）
- **データ自体が無い場合**（接続・計画書が未整備）：**CTO 石井聡明さんへのサポート依頼**や、
  **年間計画書の作成支援**を Claude に頼めます
- **定例会が終わったら**：会議音声の**文字起こしを必ずインプット**してください
  （次回資料と広告運用指示書の根拠になります）
- AI が作る**広告運用指示書**は、**コンサルタントの確認・承認後に実行**されます
  （承認依頼が来たら必ず対応してください）

## してはいけないこと（ブランド保護・ドリフト防止）
- テンプレの **CSS・色（3色）・フォント・ロゴ・レイアウトを変更しない**（変更したい場合は管理者へ）
- 数値を**手打ち・記憶で補完しない**（必ず集計データ由来）
- 「CI正本(配布)」フォルダのファイルを**編集・移動しない**（閲覧専用）
- Tier0（Shelpha 生データ）をデッキや共有フォルダに**持ち込まない**

## ファイナライザ担当向け（1台のみ・初回セットアップ）

```bash
# 前提: Mac + Google Chrome + Python3
pip3 install pymupdf python-pptx
# 変換（PDF＋画像PPTX を ci-out/ に生成）
bash 5co-CI-kit/ci-finalize.sh <デッキ.html> -o ci-out
```

- 生成された **PPTX を Drive にアップ → 右クリック →「Google スライドで開く」**＝Slides 版も完成（1ソースで両取り）。
- 変換前に品質ゲートが自動で走る（はみ出し・ロゴ幅・タイトル未置換の検査）。警告が出たら HTML を修正してから配布する。
- ゲートが OK でも、**生成された PDF を開いて目視で確認してから配布する**（＝暗黙確認）。
  特に `NEAR-MISS(警告...)` の行が表示された場合は、該当箇所が窮屈に見えないか必ず見る。
- PPTX/Slides は**1スライド=1画像（編集不可）**。文言修正は必ず HTML に戻って行い、再変換する。

### 文章を LLM に書かせた・書き直させたとき（必須・2026-09-08 追加）

やさしい版・英語版・見出しや洞察の起案など、**文章を LLM が触ったデッキは必ず検品を通す**。
数字が合っていても文言が壊れることがあり（「¥9.5M27¥0.73億」「¥3.7M個」「430位円」「個個」）、
はみ出し・重なりのゲートでは検出できない。

```bash
# 原文がある場合（やさしい版・英語版）: NG段落だけ原文へ戻す
python3 5co-CI-kit/llm_output_check.py <生成物.html> --source <原文.html> --restore
# 原文が無い場合（LLM が起案した見出し・洞察）: 禁止語とタグの破損を見る
python3 5co-CI-kit/llm_output_check.py <デッキ.html> --terms 5co-CI-kit/TERMS_AMAZON.md
```

英語版を作るときは、級数を案件側で調整せず `python3 5co-CI-kit/ci_head.py --lang en` を使う
（はみ出すときだけ `--lang-scale 0.8` のように段階的に下げる）。

### 案件スクリプトから kit を参照するとき（必須・2026-09-09 追加）

`ROOT = HERE.parents[5]` のような**階層の決め打ちで kit を指さない**。階層が1つ違うだけで
はみ出し検査が「実行されずに成功扱い」になり、例外も出ずに不備が本番に残った（2026-09-09 実事故）。
kit の `ci_paths.py` で上位ディレクトリを遡って `5co-CI-kit/VERSION` を探し、見つからなければ**その場で落とす**。

```python
import sys, pathlib
_here = pathlib.Path(__file__).resolve()
_kit = next(d / "5co-CI-kit" for d in (_here, *_here.parents) if (d / "5co-CI-kit" / "VERSION").is_file())
sys.path.insert(0, str(_kit))
from ci_paths import add_to_sys_path
kit = add_to_sys_path(__file__)   # 見つからなければ SystemExit（黙ってスキップしない）
import ci_head
```
