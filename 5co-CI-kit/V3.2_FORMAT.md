## このページの要点（gist・全CIスライド推奨・2026-09-08 v3.8 制定）

**見出しの直下に「このページの要点」を1つ置く。** 読者は要点だけを拾い読みして資料を通読できる。
COPY_GUIDE.md ルール1「1ページ1メッセージ」の**表示側の実装**にあたる。

```html
<h2 class="title">…</h2><div class="accent-bar"></div>
<p class="gist"><span class="gist-k">このページの要点</span>本文（1〜2文）</p>
<p class="t-note">図の読み方: …</p>
```

- **順序＝見出し → 要点（gist） → 図の読み方 → 本体**。この順を崩さない
- 本文は「読者の問いへの答え」（COPY_GUIDE.md ルール1）。分類名・数字の羅列で終わらせない
- **要点が1〜2文で書けないページは、1ページ1メッセージになっていない**。ページ分割を検討する
- ラベル `.gist-k` は琥珀（`--insight`）＝機能色。**要点ラベル以外に琥珀の帯を使わない**
- CSS 正典＝`ci-gist-v3.8.css`（案件ビルダーでの再定義は禁止。v3.7 以前は各案件が自前定義していた＝ドリフト）
- **表・実績ページの要点は、冒頭の OKR（目標と実績の差）から逆算した最大のギャップ要因を1つだけ書く**（2026-10-30 転記）
- **ギャップ要因には必ず施策を対で書く**（同じ文に書くか「→施策 p○」で施策ページを指す）。資料に無い施策は「施策（案）要確認」と書く（新しく作らない）。出典＝ブランドガイドブック β0.1（2026-10-29 若松さん）・`COPY_GUIDE.md` ルール9

### 洞察強調（琥珀）を付けるセルの選び方（2026-09-09 追加）

**大きい値ではなく、そのページの洞察文が実際に言及するセルに付ける。**
「洞察が言及するデータセルのみ」（不変条件）の運用でいちばん多い誤りが、
**数値が大きいセルに付けたくなる**というもの。

- **誤用の実例**（2026-09-08 WELLA OPI ネイル統合版）: 「シェア上限までの余地が大きい」という理由で、
  **計画に置けないカテゴリー**（商品が廃盤・自社価格が市場価格帯と合わない）にも琥珀を付けていた。
  読み手には「ここを取りにいく」と読めてしまうため修正した。
- 迷ったら、そのページの `.gist`（要点）と洞察文を読み返し、**文中に出てこないセルの琥珀は外す**。
- 1ページの琥珀は洞察が指す範囲に絞る（全部が強調＝どれも強調されていない）。

### 見出しの長さ（2026-09-09 追加）

**見出し（`h2.title`）は全角45字程度まで＝2行以内**に収める。実測で**全角46字前後が3行の境目**で、
3行になるとページが溢れる（用語を正式名に直すと見出しが伸びるため、v3.8 で実際に発生した）。
`slide_overflow_check.py` が3行以上を `TITLE_LINES?` として警告する（非ゲート）。
あふれたページでこの警告が出ていたら、**本文ではなく見出しを短くする**。

### 本文を差し替えるスクリプトの規則（必読・2026-09-08 追加）

やさしい版のリライト、英語版の翻訳、LLM出力の差し戻しなど、**後からページの本文だけを
書き換える処理は、`.gist` を壊しやすい**。`.gist` は「開始タグが2つある要素」だからである。

```html
<p class="gist"><span class="gist-k">このページの要点</span>本文</p>
```

- **本文の差し替えは `span.gist-k` の後ろのテキストノードだけを対象にする。**
- **開始・終了タグは検出時の文字列をそのまま使い、正規表現で作り直さない。**
  実際に `^(<[^>]+>)(.*)(<[^>]+>)$` でタグを組み直した結果、`span.gist-k`（要点ラベル）が
  消えたページが十数枚でき、配布直前に気付いた事故がある（2026-09-07 ULTIME 統合版）。
- 差し替え処理を書いたら **`llm_output_check.py` を通す**。同スクリプトは内側の文字列だけを
  原文の同じ範囲で置換する実装になっており、`--selftest` にこの事故の回帰テストが入っている。
- 本文を1要素に確定させたい場合は `<span class="gist-t">本文</span>` で包んでよい
  （`ci-gist-v3.8.css` に定義あり・**任意**。既存デッキは包まないままで動く）。

## ノード・エッジ型グラフ図（グリッド座標系・2026-07-13 制定）

ノードを自由な位置に置き、エッジ（矢印）を別要素として明示的に描くグラフ図（フロー図・
ネットワーク図）は、**座標を手で置く方式は崩れやすい**（ノード同士の意図しない重なり・
矢印終点のズレ・文言変更のたびの全座標引き直し。顧客OKR会 AI運用OODAループ資料で実証）。
そのため以下の座標規律と専用ゲートを正典とする。型の詳細・スケルトン＝
`docs/SLIDE-PATTERN/SLIDE-PATTERN-node-edge-graph/`。

- **グリッド座標系**：ノードは絶対座標の手置きでなく、**グリッド（列×行）上の位置＋幅
  （colspan）で定義**する。`col_x(i) = MARGIN + i*COL_W`／`row_y(j) = MARGIN + j*ROW_H`／
  `node = { x: col_x(i), y: row_y(j), w: colspan*COL_W - GAP, h: NODE_H }`。
  ノード数・文言量が変わっても既存ノードの座標を引き直さずに行・列の追加だけで拡張できる。
  **標準値＝8列×5行**（viewBox 880×430・MARGIN=8・COL_W=108・ROW_H=82・NODE_H=44・GAP=12
  ＝スケルトンの値）。収まらない場合は個別ノードの手伸ばしでなく**式ごと**列数・セルサイズを変える。
- **エッジの接続点**：エッジの始点・終点は必ずノードの縁の式から機械的に算出する
  （top-center=`(x+w/2, y)`・bottom-center=`(x+w/2, y+h)`・left-center=`(x, y+h/2)`・
  right-center=`(x+w, y+h/2)`）。手での微調整は禁止（＝浮いた矢印の温床）。
- **実装構成は2択**：①**純SVG構成**（スケルトンどおり・ノードも `rect` で描く。パターン変換・
  自己完結性に向く） ②**ハイブリッド構成＝node=HTML／edge=SVG**（ノード＝HTML div に
  `.ne-node` を付与＝既存CSSクラスを流用でき和文の折返し・組版はHTMLに任せる。エッジ＝
  コンテナ内に `position:absolute` で重ねた SVG）。**実運用のCIスライド本番化では②が最安定**
  （純SVG＋foreignObject より和文折返し精度が高い）。ゲートは screen 座標系で突き合わせるため
  どちらの構成でも同一に検査できる。
- **タグ付け規約（検査の前提）**：グラフのコンテナ（svg または div）に `class="ne-graph"`、
  ノード（SVG rect または HTML div）に `class="ne-node"`、エッジに `class="ne-edge"`
  （marker-end/marker-start 付きの線は無指定でもエッジ扱い）、
  凡例の見本線など意図的にノードへ繋がない線に `class="ne-skip"` を付ける。
- **専用ゲート**：`graph_node_edge_check.py` が headless Chrome で実測し、①ノード同士の
  AABB交差（NODE_OVERLAP・1px未満の接触は許容）②エッジ始点・終点がノードの縁
  （許容誤差±2.5px）に乗っていない浮き（EDGE_DETACHED）③タグ付け漏れ（NO_NODES）を
  検出して `exit 1`。既存の `slide_overflow_check.py`／`check_text_overlap.py` は
  DOM/flexboxベースの検査でSVG内座標は死角のため、本ゲートが補完する
  （`ci-finalize.sh` が自動でゲートする。ne-graph を含まないデッキには影響しない）。

## 生成・検査・出力の規定

1. **生成**：本キットのフォーマットに**文言・数値のみ**差し替え（CSS/色/フォント/レイアウト改変禁止）。数値はデータ由来のみ（手打ち・推測禁止）
   - **伝わりやすさ最優先**：文章の羅列スライドを作らない。主張・数値・比較は、内容に合う**フレームワーク図・グラフ・表**で構造化して示す（v3.2 の8型と 129種 SLIDE-PATTERN から選ぶ。型選びは `framework-recommend` スキルが支援）
   - **図は既定で使う（v3.10）**：指示が無くても、本文ページには原則すべてフレームワーク図・グラフかイラストを1つ置く。文章と表だけのページを作らない。仕上げ前に `ci-gates.sh` の「図の無いページ（FIG?）」をゼロにする（例外は `data-fig-exempt="理由"`）。`ci-finalize.sh` は FIG? で止まる＝`FIGURES_GUIDE.md` 0章
   - **文言は「問いへの答え」方式（`COPY_GUIDE.md`＝crystal text・文言の正・必読）**：タイトル＝読者の問いへの答え／チャート1文目に「図の読み方:」／判断に「なぜ」の因果／専門用語は初出で日常語併記／誠実トーンの定型
1.5 **変換（PPT・旧資料→CI）の項目一致原則**：元資料のテーブル項目（列・行・指標名・単位）を
   **欠落・改名・統合・並べ替えしない**（デザイン＝CIが正／**データ項目＝元資料が正**）。
   - はみ出しゲートに掛かっても**列を削って解消しない**。解消手段は 1:表の分割（複数スライド化）
     2:密度高の型（`pdstr` 等）への変更 3:規定内のフォント/パディング調整 の順で検討
   - 変換後、**元資料の項目リストと突き合わせて差分ゼロを確認**してから配布（照合結果を報告に含める）
1.5b **表の分離の忠実再現（2026-07-09 制定）**：原本PPTで指標群（例: Object売上／通常期日販／広告経由）や
   ブロック（例: ブランド）が**隙間で分離**されている表は、CI変換後も**同じ位置に分離を再現**する
   （1枚の格子へ統合しない＝原本の情報設計の保全）。
   - 実装＝透明スペーサー方式（ヘッダ・列幅整合が保たれ、はみ出しゲートも1表で通る）。分離を使う表に
     `class="skg"` を付与し、列グループ間はヘッダ1行目 `<th class="gp" rowspan="2">`＋各行 `<td class="gp">`、
     行ブロック間は `<tr class="brsp"><td colspan="{実列数}"></td></tr>`（colspan はスペーサー列を含む実列数）。
   - CSS は `ci-format-v3.2.css` の `table.skg .gp / tr.brsp`（正典・改変禁止）。
1.6 **共通HEAD原則（案件ビルダーの正典消費・2026-07-07 制定）**：案件の自動ビルド
   （NatureLab `build_html_monthly.py`／WELLA 等）は、正典CSSを**コピー・inline再実装せず**、
   `ci_head.py` で連結する（`html = template.replace("<!--CI_HEAD-->", ci_head.style_block())` または
   `python3 5co-CI-kit/ci_head.py` の出力を HEAD に挿入）。
   - **なぜ**：CSSを手元コピーすると正典改定（Hoefler化・縦罫撤去等）が自動で届かず、
     連結方式を案件ごとに即興実装すると、その実装差自体が新たなドリフト源になる
     （2026-07-07 WELLA 世代遅れ事故の再発防止・連結方式は正典側で1つに固定）。
   - 連結対象は `VERSION` の format: 行が唯一の宣言（版上げ時は VERSION 更新だけで全案件が追従）。
   - 出力冒頭の版スタンプ `/* 5co-CI ci_head vX.Y — … */` が「ci_head 経由で組まれた」証跡
     （parity 検査・監査の機械判定マーカー）。
2. **検査**：`slide_overflow_check.py`（あふれ）と `check_text_overlap.py`（要素同士の重なり＝absolute配置の死角）を必ず通す。ノード・エッジ図（`.ne-graph`）を含む場合は `graph_node_edge_check.py`（ノード重なり・矢印接続＝SVG内座標の死角）も通す（すべて OK になるまで配布不可。`ci-finalize.sh` が自動でゲートする）。通過後、**タイトルだけを縦に読んで主張が通るか**、**全スライドのコメント（所見・洞察・チャート注記）が誠実トーンか**を最終チェック（`COPY_GUIDE.md` 原則1・5）
   - **動く資料**は `#static` に加えて通常表示も `check_text_overlap.py --digest-mode`／`CI_OVERLAP_NO_STATIC=1` で重なりを見る。表を編集したら原本と見出し行・行順・セル文字を機械比較する（2026-10-30・上記「動く資料」）

### 1枚1操作・操作はページの構造で決まる（2026-10-30 追補・記事 v3〔2026-10-24 更新〕と OPI 試行を反映）

本文ページごとに、見出しが言いたいことの**構造**を1つ決め、その構造の操作を**1つだけ**付ける（センスで選ばない）。
操作は「見出しの判断を、読み手が自分の手で確かめられる」ものに限る。見出しと関係ない動き（飾りの動き）は入れない。
量を表す動き（棒の長さ・並び順）は値から計算する。**値はデッキに既にある数字だけ**を使う。

| 構造 | 見出しの形 | 付ける操作 | 静止状態（#static・印刷・動きを減らす） | 部品（`ci_interactive.py`） |
|---|---|---|---|---|
| 結論と根拠 | 「AはBだ（根拠はC）」 | 押すと右から根拠パネル | 本体はそのまま（パネルは出さない） | `ev_button`／`data-ci-ev` ＋ `ev_panel` ＋ `panel` |
| 切り口 | 「Xで見るとYが大きい」 | 切り口（指標・集計の立場・年）を切り替えると全部の棒が並び替わる | 見出しの判断が見える切り口 `op(static=…)` | `op(seg(...), sort="desc")` ＋ `bar_rows`（単位が切り口ごとに違うときは `fmt={状態: 書式}`） |
| 差分 | 「前→後でこう変わった」 | 前が後へ形を変え、前（または目標）が点線で残る。点線との差＝変化・不足 | 後（実績）＋点線 `op(static="後")` | `op(seg(["前","後"]), max_value=…)` ＋ `bar_rows(ghost="前")` |
| 原因と結果（因果） | 「Aを動かすとBが変わる」 | 条件をスライダーで動かすと再計算。**式を画面に出し「試算」と書く** | 資料の基準値（デッキにある値） | `op(slider(...))` ＋ `out` ＋ `formula` ＋ `define` |
| 不足と打ち手 | 「不足はX、打ち手はY」 | 打ち手をオン/オフすると不足が埋まる・残る | 打ち手はすべてオン | `op(chip(...), static_on=[…])` ＋ `data-ci-when="+打ち手"` |
| 流れと時間 | 「順に〜した／いまはここ」 | 順に組み上がる（工程・日・月の順）。時間軸に「いま」の線 | 組み上がった最終状態 | `data-ci-step`（ずらし幅は入れ物に `data-ci-stagger="260"` 等） |

- **データが無いページには操作を付けない**（例：速報の空欄ページ）。飾りの組み上がりで埋めない
- **根拠パネル**：**出所が書いてあるページにだけ**置く（旧「ほぼ全ページに付ける」を変更）。出所をこしらえてパネルを付けない。
  〔根拠パネルを「操作の数に数えない」扱い（記事どおり・構造の操作とは別に置いてよい）とするか＝**未決（若松さん回答待ち）**。決まるまでは、構造の操作と根拠パネルを同じページに置く場合も両方とも見出しの判断に直結するものに限る〕
- **因果のスライダー（CI 追加規定・案）**：入力も出力も**デッキに既にある値**の組み合わせに限る（例：月を選ぶと「広告予算 ÷ 必達目標」をその月の表の値で計算し直す）。推計・仮定値（「もし7月が100%なら」等）は置かない。式と「試算」の字を必ず画面に出す。デッキにその組が無いページは因果の操作を付けない（他の構造で付けるか、付けない）。
  〔この規定でよいか＝**未決（若松さん回答待ち）**〕
- **琥珀「このページの要点」・ヘッダー（ロゴのみ）・フッターは操作の対象にしない**（動かさない・隠さない）
- **表の扱い**：表の見出し行・列の順・行の順・セルの文字は変えない。操作は表に属性を足す（行を押せる・セルの中身をオン/オフで重ねる）か、表の隣に小さな図を足す。**表を編集したら、原本と見出し行・行順・セル文字を機械比較する**（OPI 試行の `verify_tables.py` 相当）
- **ダイジェスト**：操作の枠は本文の直下の子に置く＝ダイジェスト時は既存規則どおり隠れる（`DIGEST_GUIDE.md`）
- **素材に無い数字は置かない**（データ統治は静的デッキと同じ）。同じデッキの別ページの値を使うときは「（p07）」のようにページを添える
- 押せるものは見て分かるようにする（「内訳を見る ›」「出所と前提 ›」・ホバーで枠・ページに入った直後に1回だけ輪で知らせる）

### 静止状態（検査・PDF・印刷）

- URL 末尾の `#static`・印刷では、**組み上がった最終状態**に固定する（操作も受け付けない。印刷が終われば元の状態へ戻る）。
  OS の「動きを減らす」設定では、最終状態から始めて動きを出さないが、操作はできる
- 操作で変わるページは「見出しの判断が見える状態」に固定する：`op(static="件数比")`（切り口）／
  `op(static_on=[...])`（省略時は打ち手を全部オン）
- 検査スクリプト（はみ出し・重なり・ノード・エッジ・見た目回帰）と `ci-finalize.sh` の PDF/PPTX は `#static` で開く＝

- 静止状態は**組み上がった最終状態**（差分＝後＋点線／切り口＝見出しの切り口／打ち手＝すべてオン／流れ＝全部組み上がり）。止めても資料として読めること。
  印刷では切り替え・オンオフ・根拠ボタンを**場所を保ったまま消し**、押したときのフォーカス枠も刷らない（2026-10-30）

### フレームワーク図は `ci_frameworks.py` で描く（2026-09-08 追加）

「文章の羅列スライドを作らない」は全社ルールだが、**表とテキストに逃げやすい**のは、
CI v2 の寸法・3色で図を描く手間が大きいためだった。案件ビルダーから**関数1本**で呼べる形にする。

```python
import ci_frameworks as FW
FW.mekko(rows, h=212)          # 幅＝規模 × 塗り＝自社シェア
FW.waterfall(steps, unit="M")  # 増減の橋渡し
```

| 型 | 使いどころ |
|---|---|
| `mekko` | 規模の違う区分を横に並べ、それぞれの中での自社の位置を見せる |
| `heatmap` | 行×列（区分×価格帯など）のどこに寄っているか |
| `funnel` | 段階的な絞り込み（登録→稼働→主力） |
| `bubble` | 2軸＋大きさ。**値が数倍〜十数倍に散るときは `xlog=True`** |
| `ranges` | 低・中・高の幅と基準線（3ケースの比較） |
| `waterfall` | 現状値から目標までの増減の内訳 |
| `slope` | 時点間の推移。動かないことを示すのにも使える |
| `concentric` | 入れ子の市場（全体 ⊃ 対処可能 ⊃ 目標 ⊃ 現在） |
| `tree` | 指標の親子関係（KPIドライバーツリー） |
| `bars_line` | 棒＋折線。月次推移に自社シェアを重ねる。**観測が無い月は線を切り、観測が薄い月は棒を中抜き**にする |

- 色は**正典トークンのみ**（`--ink` / `--crystal` 系 / `--insight` 系）。新しい色を足さない
- **琥珀はその図の洞察が言及する要素だけ**に使う（装飾に使わない）
- 数値ラベルは**図の中**に置く（凡例だけに逃さない）
- **型見本**＝`python3 ci_frameworks.py --demo out.html`（9型を1枚ずつ・そのままゲートを通せる）
- 描いたら **`svg_label_check.py` を通す**（重なり・切れ・地色同色）

**`scripts/ci_pattern_adapter.py` との使い分け**：アダプタは *SLIDE-PATTERN 129種の静的な型見本 HTML* を
CI v2 へ**変換**するもの（型を探す・単発で使う）。`ci_frameworks.py` は *案件ビルダーから実データで
**描画**する*もの（毎月の更新で数値だけ差し替わるデッキ向け）。用途が違うので併存させる。

### 制作中の検査は `ci-gates.sh`／配布直前だけ `ci-finalize.sh`（2026-09-08 追加）

`ci-finalize.sh` は PDF・PPTX 変換まで走るため、**制作中の「直した→検査」の往復には重い**。
検査そのものは数秒で終わるので、制作ループでは検査だけを回す。

| いつ | コマンド | 中身 |
|---|---|---|
| 制作中（何度も回す） | `ci-gates.sh <deck.html>` | 検査のみ。**PDF を作らない**（数秒） |
| 配布直前（1回） | `ci-finalize.sh <deck.html>` | 検査＋PDF＋PPTX |

**PDF は必要なときだけ作る**（最終の目視確認と配布時）。制作中に毎回 PDF を作ると、
1回あたり数秒〜十数秒と数MBを無駄にする。AI（Claude Code）に作業させる場合は、
コマンドが1本にまとまっているぶん往復が減り、トークン消費も下がる。

### SVG で描いた図はラベル検査を通す（2026-09-08 追加）

`slide_overflow_check.py` と `check_text_overlap.py` は **HTML要素** の箱を見る検査で、
**SVG の中で描いた文字は1つの要素**として扱われる。そのため図の中で起きる次の事故を検出できない。

| 事故 | 例 |
|---|---|
| ラベル同士の重なり | 散布図・バブル図で近接した点の名前が団子になる |
| 枠の外への切れ | 右端の注記が viewBox を越えて「…の 1」で切れる |
| 地色と同色 | 濃い塗りの上に濃い文字を置いて読めない |

`svg_label_check.py <html>` で機械検出する（文字幅は東アジア文字幅から推定・レンダリング不要）。
`ci-finalize.sh` が自動で実行する。**当面は警告扱い**（既存デッキに未修正のものが残るため）だが、
**新規に作った／改訂したページで出たものは必ず直す**。

直し方の定石は3つ。①**横軸が線形で左端に固まる**なら対数軸にする ②**ラベルが並ぶ**なら
上下にずらして引き出し線でつなぐ ③**注記が切れる**なら図の余白（pad）を広げるか文言を短くする。

### シェア目標の分母は「対処可能市場」にする（2026-09-08 制定・全案件必須）

**シェア率の目標を立てるときは、分母を「自社が実際に取りにいける範囲」に限定する。**
市場全体を分母にすると、到達しえない規模を「余地」として数え、目標も余地も過大になる。

判定は次の1問で足りる——**その市場のうち、自社の商品が実際に競合できるのはどこまでか。**

| 状況 | 分母にするもの |
|---|---|
| 既にそのカテゴリーで売っている（価格帯をまたいで売れている） | **カテゴリー全体** |
| 未出品で、参入する価格帯・用途・容量が決まっている | **その範囲だけ**（価格帯・セグメント） |
| 商品の価格がその市場に存在しない価格帯にある | **その市場は分母にしない**（参入条件の見直しが先） |

- 資料には**分母として何を使ったかを必ず列または注記で明示**する（読者が「カテゴリー全体の◯%」と誤読するため）
- 分母を絞ったカテゴリーと絞っていないカテゴリーを**同じ表で並べるときは、分母の列を設ける**
- 合計シェアを出すときは**分母が同じものだけを合算**する（混在した合計は出さない）

**根拠（2026-09-08・WELLA OPI ネイル統合デッキ）**：ジェルネイルカテゴリー（月¥55.5M）に OPI は未出品で、
参入できるのは¥2,000–2,999の価格帯（月¥8.7M）のみ。当初はカテゴリー全体を分母にしており、
シェア上限までの余地を **¥14.80M** と算出していた。対処可能市場に直すと **¥1.17M** で、**12倍の過大**だった。
目標額そのものは変わらない（価格帯の実測から積んでいたため）が、シェアは 1.5%→**11.7%** となり、
「カテゴリーの端くれ」ではなく「参入する価格帯の1割強を取る計画」と正しく読めるようになった。
