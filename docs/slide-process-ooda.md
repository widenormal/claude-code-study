## 全体像

**North Star（北極星）＝インクリメンタルセールス**（総売上の継続的向上・市場シェアの拡大）を
頂点に、**Observe → Orient → Decide → Act を月次で回す**。スライド（資料）はこのループの
Orient〜Decide をつなぐ中間成果物であり、単発の制作物ではない。

```
Observe（観察・データ収集）→ Orient（状況判断・資料化）→ Decide（人間の判断）→ Act（実行）
     ↑                                                                          │
     └────────────── 月次ループ（実運用結果で検証・見直し）───────────────────────┘
```

## 検証・改善工程（Decide の前・提出前に必ず通す）

順に適用する。①②は全制作物に必須、③は該当時必須、④は必要時のみ。

1. **決定論ゲート（必須）**：`slide_overflow_check.py`＋`check_text_overlap.py`
   （ノード・エッジ図があれば `graph_node_edge_check.py`）→ ゲートOK後も**暗黙確認**
   ＝レンダリング目視（`V3.2_FORMAT.md` 規定2.5）
2. **review-loop（HTML段階で必須）**：5エージェント（論理／読者目線／抜け漏れ／ファクト／
   敵対的）を Critical/Major ゼロまで最大5ラウンド。**観点2（読者目線）は「文章の羅列スライド」
   （図・表・グラフで構造化されていない主張・数値・比較）を Major として検出する**。
   **5ラウンドで残る指摘は「未収束項目」として人間判断へ**（`.claude/skills/review-loop/SKILL.md` の既定）
3. **Codex 差異チェック（原本がある変換・週次デッキは提示前必須）**：前提資料・前週デッキ・
   元PPTとの数値差異を独立系統で照合（`ci-weekly-deck` Step 3／`codex-review.md`。
   指摘は 採用／却下（根拠付き）／延期／未検証 の4分類）
4. **外部LLM検証（必要時）**：ルーティングは `.claude/skills/llm-router.md` が正
   （例：デザイン・マルチモーダル観点＝Gemini、出典付きWeb照合＝OpenRouter `--online`）

## 入力ゲートとアラート（定例会資料の作成時・必須）

社員がテンプレートで定例会資料を作る際、Claude セッションは次のゲートを通す
（**1〜4＝生成に入る前**の入力ゲート、**5〜6＝会議後・実行前**にループを閉じる必須手順）。
**欠損を推測・ダミー値で補完して先へ進まない**（原本ファースト・数値はデータ由来のみ）。
所在が未定義の項目は、**欠損と断定する前にまずユーザーへ所在を確認**する。

1. **Observe 入力ゲート**：図の Observe 列のデータ（広告実績＝自社DWH・Shelpha・ECモール
   商品データ・Amazon月間検索Vol・前回定例会の議事録/文字起こし・クライアント戦略文書）が
   揃っているか確認する
2. **Orient 入力ゲート**：OKR進捗（必須）と**年間計画書**（年間目標推移の元データ）が
   入力されているか確認する
3. **欠損時のアラート**：欠損があれば、**まず担当コンサルタントへの「データ欠損アラート」**
   （何が・どの期間・どこで欠けているか明示）の連絡文を作成し、送付を依頼する
4. **データがそもそも存在しない場合**（アラートの結果「ソース未接続・計画書が未作成」と
   確定した場合）：**CTO 石井聡明さんへのサポート依頼**（データソース接続・権限付与）や、
   **年間計画書の作成支援**を提案する（コンサルタント確認より先に CTO へ直行しない）
5. **会議後の入力（次サイクルの Observe・必須）**：定例会後は**会議音声の文字起こしを
   必ずインプット**するようリマインドする（Decide の必須成果物・次の広告運用指示書の根拠）。
   保存先はクライアント作業フォルダの議事録規約に従う（未定義なら所在確認）。
   **受領の検証は次回の入力ゲート（規則1）が担う**
6. **ACT の確認と承認**：AI が広告運用指示書を作成・更新する際は、**実行（ACT）前に
   コンサルタントの確認・承認を必ず依頼**する（承認なしで入札・予算・KWメンテへ反映しない
   ＝Decide を AI の外に置く工程の徹底）。経路＝Claude が指示書ドラフトと承認依頼文を作成 →
   担当コンサルタントへ提出 → 承認記録後に反映。**承認記録＝承認者名・日時（または
   承認スレッドの URL）を指示書に残す**
7. **正当に存在しない入力の免除**：初回定例（前回文字起こしが無い）・年間計画が対象外の
   クライアント等、入力が**正当に存在しない**場合は、担当コンサルタントの承認で当該項目を
   免除できる（免除した旨と理由を資料の前提注記に残す＝欠損の握り潰しと区別する）

## 不変条件（このプロセスでも変わらないもの）

- 5co公式CIスライドは **決定論パスが既定**（`CLAUDE.md` CI節・`CI_KICKOFF.md`）
- 数値はデータ由来のみ・3色ルール・検査ゲート・暗黙確認・項目一致原則
- **原本ファースト**（`CLAUDE.md` 禁止事項）：訂正/不備対応は原本を確認するまで手順を確定しない
