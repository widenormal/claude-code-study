## 3. 判断の目安（委託するかどうか）

次のどれかに当てはまれば、委託を検討する。これは目安であり、必ず守る硬いしきいではない。

- ツール呼び出しが2往復を超える
- 長文を読む、または長文を書く
- 同じ処理を繰り返す

定時ルーチンで、処理がごく小さいときは、Grokのまま行ってよい。
委託の前に、Jevで回し先を短く判定してよい。判定は1往復で終える。

## 頼んだまま止めない（2026-11-16 20:59 JST 若松さん承認）

- `codex exec` はバックグラウンド（`block_until_ms 0`）で起動し、完了通知を待つ。
- 起こし方は `claude -p` と `muse-run` も同じ。Shell ツールのバックグラウンド（`block_until_ms 0`）で起動し、完了通知で起きる。ポーリングしない。
- `nohup` / `setsid` / `disown` / 末尾 `&` だけで切り離さない。切り離すと作業の完了で起きない。
- 「終わったらお送りします」と言うなら、その仕事に追跡付き起動（`block_until_ms 0`）か完了webhookが付いていること。付いていなければ、そのターンの中で待つ。完了webhookは鍵の準備（伏見・久我）が済むまで使わない。
- 若松さんや依頼元へ「進める／送る／登録する」など完了や着手を約束する文は、同じターンでその作業の開始呼び出しを出したあとにだけ書いてよい。出せないときは約束せず、未着手と理由を書く。（2026-11-19 14:27 JST 若松さん決定。正本 2026-11-16_no-silent-stall.md 第6.5節）
- 順番作業（AのあとB）は可能な限り1本の起動で `A && B` につなぐ。つなげないときは progress.md に `NEXT | … | wait_for:DONE | status:pending` を1行書く。起動していない次について「終わったら始めます」は禁止。（2026-11-19 17:24 JST 若松さん決定。正本 2026-11-16_no-silent-stall.md 第6.6節）
- progress.md の先頭行に自分のBot名を書く（汐見が毎時7〜21時に、30分以上止まった作業を元のBotへ促す）。正本：`/workspace/knowledge/agents/rules/2026-11-16_no-silent-stall.md`（2026-11-16 20:59 JST 若松さん承認）。

## 用語を勝手に作らない（2026-11-22 16:29 JST 若松さん承認）

正本：`/workspace/knowledge/agents/rules/2026-11-22_no-invented-terms.md`
- ①用語を自分で作らない。言い換えや通称（例：Amazon直販、1P/3P）を公式の用語のように使わない。
- ②わからない・自信のない用語は、使う前にその会社・サービスの公式ドメインで確かめ、出どころのリンクを付ける。
- ③公式で確かめられないときは、その言葉を使わずに中身を説明するか「公式では確認できなかった」と書く。
- ④取り次ぎ先LLMへの指示文にもこの決まりを書き、LLMが出した用語も提出前に同じように確かめる（handoff-context-layers の1）。
- ⑤社内で決まった用語（例：GMV、Handoff Mode）は正本のmdのとおりに使う。
- ⑥判断を求める質問を出す前に、質問に出てくる業界・サービスの言葉をすべて抜き出し、1語ずつ公式の出典リンクか社内の正本の定義を付ける。どちらもない言葉は質問に使わない。
- ⑦データをもとに質問するときは、先に列の実際の値と件数を確かめ、その値をそのまま見せてから意味を書く。意味が推測なら「推測」と書く。
- ⑧判断を仰ぐ方針文書・計画書は、末尾に用語一覧（言葉／意味／出典）を付けてから出す。LLMに書かせた文書は、LLMに用語一覧を作らせ、取り次ぐBotが出典を開いて確かめる。
- ⑨同じ件で用語を2回聞き返されたら、説明を足さずにいったん止め、⑥〜⑧をやり直した質問を1通で出し直す。その件は不合格記録に「原因：用語」として残す（汐見が毎週数える）。
